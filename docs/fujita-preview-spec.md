# 投稿確認プレビュー 仕様書（藤田鉄工所／KING PLANTS）

SNS投稿（動画＋文章）を実際の投稿画面そっくりの見た目で先方に確認してもらい、その場で承認・修正依頼を受け取るための静的Webアプリ。

**コードは1つ、デプロイ先は2つ。** 藤田鉄工所用とKING PLANTS用で、見せる相手も見せる中身も違うため
（一方の未公開案件がもう一方に見えてはいけない）、データもURLも完全に分離する。
違いは `config.js` だけに閉じ込め、HTML/CSS/JSは共通のものを使う。

---

## 1. 全体構成

```
Googleスプレッドシート「藤田鉄工所＿インスタ管理シート_2026」
  ├─ シート「投稿確認」  … 確認してほしい投稿の一覧（正本）
  └─ シート「確認ログ」  … 承認／修正依頼の記録（追記のみ）
              ↑↓  Google Apps Script（Web App）をAPIとして経由
静的サイト（GitHub Pages / bonjotuy.github.io）
              ↓  iframe埋め込み
Googleドライブ上の動画ファイル
```

投稿データはスプレッドシートが正本。サイト側にJSONを持たせない。
スプシに1行足せばプレビューに1件増える、という運用にする。

## 1-2. クライアントごとの分離

```
リポジトリ（共通のHTML/CSS/JS）
  ├─ /fujita-8k3mz9/     config.js → 藤田鉄工所用スプシのGAS URL
  └─ /kingplants-p4vq2r/ config.js → KING PLANTS用スプシのGAS URL
```

- スプレッドシートはクライアントごとに別ファイル。GASもそれぞれのスプシに紐づけて個別にデプロイする
- 共通コードを直したら両方に反映される。データは絶対に混ざらない
- URLは互いに教えない

### config.js で差し替えるもの

```js
const CONFIG = {
  clientName: '藤田鉄工所',
  gasUrl: 'https://script.google.com/macros/s/xxxx/exec',
  reviewers: ['米倉社長', '吉田さん', '三浦さん'],
  accounts: [
    { key: 'stainless',  label: 'ステンレス',   handle: 'fujita_stainless' },
    { key: 'kingplants', label: 'KING PLANTS', handle: 'kingplants_pot' },
    { key: 'youtube',    label: 'YouTube',     handle: '藤田鉄工所' }
  ],
  showAccountTabs: true
};
```

KING PLANTS版の config.js:

```js
const CONFIG = {
  clientName: 'KING PLANTS',
  gasUrl: 'https://script.google.com/macros/s/yyyy/exec',
  reviewers: ['小野寺さん'],
  accounts: [
    { key: 'stainless',  label: 'ステンレス',   handle: 'fujita_stainless' },
    { key: 'kingplants', label: 'KING PLANTS', handle: 'kingplants_pot' }
  ],
  showAccountTabs: false,
  collabDefault: true
};
```

確認者が小野寺さん1人なので、`reviewers` が1件のときは名前選択画面を出さず、自動でその人として扱う。

## 2. スプレッドシートのシート構成

### シート「投稿確認」

| 列 | 名前 | 内容 |
|---|---|---|
| A | id | `p001` のような一意のID |
| B | アカウント | `stainless` / `kingplants` / `youtube` のいずれか |
| C | 投稿タイプ | `reel` / `feed` / `story` / `short` |
| D | 予定日時 | 2026-08-12 19:00 |
| E | 動画URL | ドライブの共有リンクをそのまま貼る |
| F | キャプション | 本文。セル内改行OK |
| G | ハッシュタグ | スペース区切り |
| H | ステータス | `確認待ち` / `OK` / `要修正`（GASが自動更新） |
| I | 表示 | `TRUE` の行だけサイトに出す |
| J | 共同投稿 | `TRUE` のとき投稿者名を2つ並べて表示する |

投稿IDは藤田鉄工所版とKING PLANTS版で**同じidを使う**。同じ動画を両方に載せるので、
突き合わせるときにIDが揃っていないと追えなくなる。

### シート「確認ログ」

| 列 | 名前 |
|---|---|
| A | 日時 |
| B | 投稿ID |
| C | 確認者（米倉社長／吉田さん／三浦さん） |
| D | 結果（OK／要修正） |
| E | コメント |

追記のみ。上書きしないので、誰が何と言ったかが全部残る。

## 3. 画面仕様

### 3-1. 初回の名前選択

- `CONFIG.reviewers` が2件以上のときだけ表示する
  （藤田鉄工所版：米倉社長／吉田さん／三浦さん の3択。KING PLANTS版：小野寺さんのみなので**画面を出さない**）
- `localStorage` に保存し、2回目以降はスキップ
- 画面の隅に「◯◯として確認中／切り替える」を常時表示しておく（間違えて選んだとき用）
- パスワードは設けない。URLをランダム文字列にすることで実質的な限定公開とする

### 3-2. 一覧画面

- 上部にアカウント切り替えタブ（ステンレス／KING PLANTS／YouTube）
- 未確認の件数をバッジ表示
- カードを縦に並べる。各カードは投稿タイプに応じたレイアウト（下記）
- ステータスが `OK` のものは薄く表示し、下にまとめる

### 3-3. Instagram リール レイアウト

- 左：9:16の動画エリア（幅230px前後）
- 上部：アカウントのアイコン＋ユーザー名＋「投稿予定 ◯月◯日 ◯◯:◯◯」
- 共同投稿のときは実際のInstagramと同じく **2アカウント名を並べる**
  （アイコンを重ねて表示し、`fujita_stainless と kingplants_pot` の形式）
- 右：いいね／コメント／シェア／保存のアイコン列（飾りのみ、押せなくてよい）
- キャプション本文（改行そのまま）、ハッシュタグは青文字
- 下部に「これでOK」「修正したい」ボタン

### 3-4. Instagram フィード レイアウト

- 1:1 または 4:5 の画像エリア
- 複数枚のときは横スワイプできるようにする（ドットインジケータ付き）
- それ以外はリールと同じ

### 3-5. YouTube レイアウト

Instagramの見た目だと違和感が出るので別レイアウトにする。

- 16:9 のプレイヤー（Shortsの場合は9:16）
- 下にタイトル（太字・大きめ）
- チャンネル名（藤田鉄工所）
- 概要欄テキスト（折りたたみ「…もっと見る」つき）
- タグ

### 3-6. 「修正したい」を押したとき

- その場でコメント入力欄が開く（別ページに飛ばさない）
- KING PLANTS版のプレースホルダーは共同投稿の確認観点に寄せる
  例：「店名の表記、植物の品種名、映り込みなど、気になる点があれば」
- 送信 → GASにPOST → 「送信しました」表示 → カードのステータスを更新
- コメントは必須。空なら送信させない

### 3-7. すでに他の人が確認済みのとき

- カード下部に確認ログを表示する
  例）「吉田さん：要修正（8/5 14:20）— 溶接シーンをもう少し長く」
- 3人が見るので、同じ指摘が重複しないように過去のコメントは必ず見せる

## 4. GAS Web App API 仕様

デプロイ設定：実行ユーザー＝自分、アクセス＝全員（匿名含む）

### GET（投稿一覧の取得）

```
GET {WEB_APP_URL}
```

レスポンス
```json
{
  "ok": true,
  "posts": [
    {
      "id": "p001",
      "account": "stainless",
      "type": "reel",
      "scheduledAt": "2026-08-12 19:00",
      "videoUrl": "https://drive.google.com/file/d/xxxx/view?usp=sharing",
      "caption": "project 03／スクリュージャックスツール\n\n...",
      "hashtags": "#ステンレス #オーダーメイド家具 #気仙沼",
      "status": "確認待ち",
      "logs": [
        { "at": "2026-08-05 14:20", "by": "吉田さん", "result": "要修正", "comment": "..." }
      ]
    }
  ]
}
```

### POST（承認・修正依頼の送信）

```
POST {WEB_APP_URL}
Content-Type: text/plain   ← 重要。application/json にするとCORSプリフライトで弾かれる
```

ボディ
```json
{
  "id": "p001",
  "by": "米倉社長",
  "result": "要修正",
  "comment": "溶接シーンをもう少し長く"
}
```

処理：
1. 「確認ログ」シートに1行追記
2. 「投稿確認」シートの該当行のH列を更新
3. ぼんちゃん宛にメール通知（`MailApp.sendEmail`）

## 5. 動画の埋め込み

セルに貼られたドライブの共有リンクからファイルIDを抜き出して変換する。

```js
function driveId(url) {
  const m = String(url).match(/[-\w]{25,}/);
  return m ? m[0] : null;
}

// 動画プレイヤー
`https://drive.google.com/file/d/${id}/preview`   // iframeのsrc

// サムネイル（一覧の軽量表示用）
`https://drive.google.com/thumbnail?id=${id}&sz=w400`
```

**必須の下準備**：対象の動画ファイル（またはフォルダ）を「リンクを知っている全員が閲覧可」にしておく。
ここが限定共有のままだと、先方がスマホの別アカウントで開いたときに真っ黒になる。

## 6. デザイン方針

- 本物のInstagram / YouTubeのUIに寄せるが、公式ロゴは使わない（アイコンは汎用のものに置き換える）
- スマホで見る前提。1カラムで縦に積む。ボタンは指で押しやすいサイズに
- 動画は自動再生しない。タップで再生
- 読み込み中はスケルトン表示

---

## 7. 実装の順番

1. GASのWeb Appを先に作り、ブラウザでURLを叩いてJSONが返ることを確認
2. 一覧＋リールレイアウトだけ作る（読み取り専用）
3. 入場画面（合言葉＋名前選択）
4. 承認・修正依頼のPOST処理
5. 確認ログの表示
6. フィード／YouTubeレイアウト
7. GitHub Pagesにデプロイ

### 運用上の注意

- 許可待ちの案件（バイク神社のようにキョウシンさん側の確認が要るもの等）は、許可が下りるまでシートに載せない。
  URLが実質公開なので、載せた時点で外に出る前提で扱う
- KING PLANTSさんが写っている動画は、**先にKING PLANTS版で承認をもらってから**藤田鉄工所版に載せる。
  順番を逆にすると、まだ本人の許可が下りていない映像を藤田鉄工所側が見て「OK」を押す状態になる

## 9. 2つ目（KING PLANTS版）の立ち上げ手順

1. KING PLANTS用に新しいスプレッドシートを作り、「投稿確認」「確認ログ」の2シートを用意
2. そのスプシのApps Scriptに同じGASコードを貼り、`NOTIFY_MAIL` を設定してデプロイ
3. リポジトリに `/kingplants-xxxxxx/` を作り、`config.js` だけ新規作成。他のファイルは共通のものを参照する
4. 動画は同じドライブでよいが、KING PLANTS用フォルダを分けておくと共有設定の事故が減る

### 共同投稿の運用フロー

1. 動画とキャプションができたら、まずKING PLANTS版のシートに載せる
2. 小野寺さんが承認 → 確認ログに記録される
3. 同じidで藤田鉄工所版のシートに載せる
4. 社長・吉田さん・三浦さんが確認
5. 両方OKで投稿。Instagramの共同投稿としてKING PLANTS側を招待する

## 10. 実装で変えたところ（2026-08-03）

この仕様書は最初の設計。実装にあたって次を変更した。現状の正は `README.md`。

- **一覧をやめ、1画面＝1投稿の全画面表示にした。** 上下スワイプで次の投稿へ。
  実際のInstagramリール／フィード、YouTubeショートの画面をそのままなぞる
  （右のアイコン列、左下のアカウント行・音源・キャプション、下のタブバー）
- **キャプションはタップで下からシートが上がってきて全文を読む形にした。**
  確認ログはそのシートの中にコメントのように並ぶ。判定ボタンはシートの一番下と画面下部の2か所
- **アカウントのタブ名を「プロジェクト／プロダクト／YouTube」に変更。**
  シートB列に書く値もそれに合わせて `project` / `product` / `youtube`
- KING PLANTS版はプロダクトのみを共有するため、タブそのものを出さない（`showAccountTabs: false`）
- シートに任意列を追加：**K列「音源」**（リールの音源表示）、**L列「場所」**（位置情報表示）
- GASの `doGet` が J列（共同投稿）・K列・L列も返すようにした
