# 投稿確認プレビュー（藤田鉄工所／KING PLANTS）

SNS投稿（動画＋文章）を実際の投稿画面そっくりの見た目で先方に見てもらい、
その場で「これでOK」「修正したい」を受け取るための静的Webアプリ。

仕様は `docs/fujita-preview-spec.md` を参照。

---

## ファイル構成

```
assets/app.css          共通スタイル（両クライアントで共有）
assets/app.js           共通スクリプト（両クライアントで共有）
gas/fujita-preview-gas.gs   スプレッドシートに貼るGoogle Apps Script

fujita-8k3mz9/          藤田鉄工所版（index.html + config.js）
kingplants-p4vq2r/      KING PLANTS版（index.html + config.js）

_dev/                   ローカル確認用のダミーデータ。GASにはつながない
```

**クライアントごとの違いは `config.js` だけ。** HTML/CSS/JSは共通のものを参照しているので、
`assets/` を直せば両方に反映される。スプシもGASのデプロイも別なので、データは混ざらない。

`_dev/` は先頭がアンダースコアのため GitHub Pages（Jekyll）では公開されない。
ルートに `index.html` は置いていないので、URLのディレクトリ名を知らない人は何も見られない。

## セットアップ

### 1. スプレッドシート

管理シートに次の2枚を追加する（1行目は見出し）。

**シート「投稿確認」**

| 列 | 名前 | 内容 |
|---|---|---|
| A | id | `p001` のような一意のID |
| B | アカウント | `project` / `product` / `youtube` / `note`（画面のタブ名 プロジェクト／プロダクト／YouTube／note に対応） |
| C | 投稿タイプ | `reel` / `feed` / `story` / `short` / `video` / `note` |
| D | 予定日時 | 2026-08-12 19:00 |
| E | 動画URL | ドライブの共有リンク、または `videos/p001.mp4`（→「動画の置き方」）。複数枚のときはカンマ区切り。**noteのときは見出し画像を1枚だけ** |
| F | キャプション | 本文。セル内改行OK。**YouTubeとnoteは1行目がタイトル、2行目以降が概要欄／本文になる** |
| G | ハッシュタグ | スペース区切り |
| H | ステータス | `確認待ち` / `OK` / `要修正`（GASが自動更新） |
| I | 表示 | `TRUE` の行だけサイトに出す |
| J | 共同投稿 | `TRUE` のとき投稿者名を2つ並べる。空欄なら `config.js` の `collabDefault` に従う |
| K | 音源 | 任意。リールの音源表示に出す（例 `米津玄師 · 烏 - Raven`）。空欄なら「オリジナル音声・アカウント名」 |
| L | 場所 | 任意。Instagramの位置情報のように表示する（例 `鳥海山`） |
| M | ドキュメントURL | 任意。**入っているとF列より優先され、GASがそのGoogleドキュメントを読んで本文にする**（→「ドキュメントから本文を読む」） |
| N | プレビューURL | 任意。noteの下書きプレビューなど。「noteでプレビューを見る」ボタンが出る（→「noteのプレビューリンクで確認する」） |

**シート「確認ログ」**

| 列 | A | B | C | D | E |
|---|---|---|---|---|---|
| | 日時 | 投稿ID | 確認者 | 結果 | コメント |

追記のみ。誰が何と言ったかが全部残る。

### 2. GAS

1. 管理シートを開き、拡張機能 → Apps Script
2. `gas/fujita-preview-gas.gs` の中身を貼る
3. `NOTIFY_MAIL` を自分のメールアドレスに書き換える
4. デプロイ → 新しいデプロイ → ウェブアプリ
   - 実行ユーザー：**自分**
   - アクセスできるユーザー：**全員**
5. 出てきた `.../exec` のURLを控える
6. ブラウザでそのURLを直接開き、JSONが返ることを確認する

KING PLANTS用のスプシでも同じ手順をもう一度やる（デプロイは別になる）。

### 3. config.js

`fujita-8k3mz9/config.js` と `kingplants-p4vq2r/config.js` の `gasUrl` を、
それぞれ控えたURLに差し替える。

### 4. 動画の共有設定

対象の動画ファイル（またはフォルダ）を **「リンクを知っている全員が閲覧可」** にする。
ここが限定共有のままだと、先方がスマホの別アカウントで開いたときに真っ黒になる。

### 5. デプロイ

このフォルダをそのままリポジトリに入れて GitHub Pages を有効にする。ビルド不要。

```
https://bonjotuy.github.io/<repo>/fujita-8k3mz9/
https://bonjotuy.github.io/<repo>/kingplants-p4vq2r/
```

パスワードは設けていない。URLのランダム文字列が実質の鍵なので、**2つのURLは互いに教えない。**

## 運用上の注意

- 許可待ちの案件は、許可が下りるまでシートに載せない。URLが実質公開なので、載せた時点で外に出る前提で扱う
- KING PLANTSさんが写っている動画は、**先にKING PLANTS版で承認をもらってから**藤田鉄工所版に載せる。
  順番が逆だと、まだ本人の許可が下りていない映像を藤田鉄工所側が見て「OK」を押す状態になる
- 投稿IDは両版で同じものを使う。突き合わせるときにIDが揃っていないと追えなくなる

## 画面の作り

**方針：見た目の再現より「確認しやすさ」。**
一度はInstagram／YouTubeの画面をそっくり再現したが、動画をタップするとGoogleドライブの
プレイヤーが立ち上がり、黒い幕と操作パネルが画面全体を覆って文章も判定ボタンも押せなくなった。
ドライブのプレイヤーはiframeの中身なのでこちらからは消せない。

そこで**動画を決まった大きさの枠に閉じ込め、ドライブのパネルがその枠の外に出られないようにした。**
文章と判定ボタンは常に読める・押せる状態が保たれる。

### 1投稿＝1カード、縦にスクロール

```
┌────────────────────┐
│ 確認待ち  リール  共同投稿      │ ← 状態がひと目でわかる
│ プロジェクト ・ 投稿予定 8月12日(水) 19:00 │
├────────────────────┤
│        ┌────┐            │
│        │ 動画 │  ← 高さ56vhの枠  │
│        └────┘            │
│ 再生ボタンを押すと動画が始まります │
├────────────────────┤
│ 投稿文                          │
│ （全文をそのまま表示。改行も維持）│
│ #ハッシュタグ                    │
├────────────────────┤
│ これまでの確認                   │
│ 吉田さん 要修正 8/5 溶接シーンを… │
├────────────────────┤
│ [ これでOK ]  [ 修正したい ]     │
└────────────────────┘
```

- **文章は最初から全文表示。**タップして開く操作をなくした
- 動画の下に「**ドライブで見る**」。押すと別タブでドライブが開き、大きく見られる
- ドライブのプレイヤーは中身を触れないので、iframeを1.6倍で描画して0.625倍に縮小している。
  動画の見える大きさは変わらないまま、ボタンや操作バーだけが約6割になる
- 上部に「未確認 2件 ／ 全3件」。残りがすぐわかる
- 自分が未確認のカードが上、確認済みは薄く下にまとまる
- OKを押すと、次の未確認カードまで自動でスクロールする
- 動画の枠は 縦動画=9:16 / フィード=4:5 / YouTube動画=16:9 / noteの見出し画像=1280:670

### 動画の置き方

E列には3通り書ける。**基本はドライブの共有リンクでよい。**

| 書き方 | 動き |
|---|---|
| ドライブの共有リンク | ドライブのプレイヤーで再生。タップ直後の数秒だけ枠内に操作パネルが出る |
| `videos/p001.mp4` | サイトに置いたファイルを素で再生。パネルなし。ただし**gitの履歴に永久に残り、リポジトリが膨らむので非推奨** |
| `https://…/p001.mp4` | 外部に置いた動画を素で再生。パネルなし。R2やS3などを使う場合はこれ |

> ⚠️ ドライブの動画を `<video>` で直接再生する方法は使えない。
> `drive.usercontent.google.com` は `cross-origin-resource-policy: same-site` を返すため、
> ブラウザが他サイトからの読み込みを拒否する（curlでは通るので検証時に誤解しやすい）。

### note記事の書き方

B列とC列に `note` と書けば、noteの記事として表示される。

- **E列＝見出し画像**（1枚だけ）。ドライブの共有リンクでも、外部の画像URLでもよい。
  実際のnoteと同じく **横長（1280×670）に切り抜いて**表示するので、
  ここで文字が切れて見えるなら本番でも切れる
- **F列の1行目がタイトル**、空行をはさんで2行目以降が本文。YouTubeと同じ決まり
- 本文は簡単な記法をそのまま反映する。ライターがnoteの下書きから貼り付ければ、だいたいそのまま出る

| 書き方 | 表示 |
|---|---|
| `## 見出し` | 大見出し |
| `### 見出し` | 小見出し |
| `> 引用文` | 引用（左に線） |
| `- 項目` | 箇条書き |
| `---` | 区切り線 |
| `**強調**` | 太字 |
| `https://…` | リンク |

- 空行で段落が分かれる。段落の中の改行はそのまま改行になる
- タイトルの下に **本文の文字数**（空白・改行を除く）を出している。分量の目安に使う
- 記事なので「共同投稿」バッジは出さない。日時の表記も「公開予定」になる

### ドキュメントから本文を読む

ライターさんから初稿がGoogleドキュメントで届く場合、**M列にそのURLを貼るだけ**でよい。
GASがドキュメントを開いて中身を取り出し、上のnoteレイアウトに流し込む。コピペはしない。

ドキュメントを直せば、先方がアプリを開き直した時点で新しい内容になる。

**ドキュメントの読み替えかた**

| ドキュメント側 | 表示 |
|---|---|
| タイトル／見出し1 | 記事タイトル（先頭にあるとき）。以降は大見出し |
| 見出し2 | 大見出し |
| 見出し3以下 | 小見出し |
| 箇条書き | 箇条書き（入れ子は1段に均される） |
| **太字** | 太字 |
| 区切り線 | 区切り線 |
| 貼り付けた画像 | 本文中にそのまま表示（順番も保つ） |
| 表 | 表示されない。「元のドキュメントで確認してください」と出る |

- 引用にしたい行は、ドキュメント側で行頭に `＞` を書く（Docsに引用スタイルがないため）
- **タイトルはドキュメントの先頭の見出しを使う。**見出しがなければファイル名になる
- F列は空でよい。両方入っている場合はM列が勝つ。ドキュメントが読めなかったときだけF列が出る
- M列はnote以外（リール・YouTubeなど）でも使える。長い概要欄をドキュメントで書きたいときに便利

**画像の扱い**

ドキュメント内の画像は、GASがマイドライブの `投稿確認_ドキュメント画像` フォルダに複製し、
そのリンクを画面に出す。フォルダは初回に自動で作られる。同じ画像は2回目以降アップロードしない。

- 1記事につき30枚まで。25MBを超える画像は飛ばす
- 溜まった画像を消したいときは、Apps Scriptのエディタで `cleanupImageCache` を実行する
  （ゴミ箱に移すだけ。次にアプリを開いたときに作り直される）

**共有設定**

ドキュメントは **GASを動かしている自分のアカウントから読める状態**にしておく。
自分が作ったものか、共有してもらっていれば問題ない。読めないときは画面に注意書きが出る。

**この機能を使うにはGASの再デプロイが必要**（→「GASを更新するとき」）。
ドキュメントとドライブを触る権限が増えるので、承認をやり直すことになる。

### noteのプレビューリンクで確認する

ライターさんからnoteの下書きプレビュー（`https://note.com/preview/…?prev_access_key=…`）が
届く場合は、**N列にそのURLを貼る**。カードに「noteでプレビューを見る」ボタンが出て、
別タブでnoteが開く。先方はそこで読んで、戻ってきてOK／修正を押す。

**枠内に埋め込むことはできない。**noteが他サイトからの埋め込みを拒否しているため、
iframeで貼っても真っ白になる（実際に試して確認済み）。
また note.com は `/preview/` への自動アクセスを robots.txt で禁止しているので、
GASで中身を取ってくる方式も採らない。

F列・M列と組み合わせて、こう使い分ける。

| 入っている列 | 画面 |
|---|---|
| N列だけ | タイトルと「noteでプレビューを見る」ボタン。本文欄は出ない |
| M列（またはF列）だけ | 本文をアプリ内で全文表示。今までどおり |
| 両方 | 本文をアプリ内に表示し、その下に「実際の見た目はこちらで確認できます」＋ボタン |

- N列だけのときも、**F列にはタイトルを1行入れておく**とカードで判別できる。空だと「(タイトル未設定)」になる
- プレビューURLは下書きを作り直すと変わることがある。差し替わったらN列も貼り直す
- N列はnote以外の投稿でも使える（外部のプレビューページを見せたいときなど）

### GASを更新するとき

1. 管理シート → 拡張機能 → Apps Script
2. `gas/fujita-preview-gas.gs` の中身で**すべて置き換える**（`NOTIFY_MAIL` の書き換えを忘れずに）
3. 右上 デプロイ → **デプロイを管理** → 鉛筆アイコン → バージョン「新バージョン」→ デプロイ
   - ここで「新しいデプロイ」を選ぶと**URLが変わってしまい、`config.js` の差し替えが必要になる**
4. 権限の確認が出るので承認する（ドキュメントとドライブの読み書きが増えているため）
5. ブラウザで `.../exec` を直接開き、JSONが返ることを確認する

### 「DocumentApp.openById を呼び出す権限がありません」と出たとき

承認が古いまま。コードの問題ではない。

**実行しても承認画面が出ないときは、マニフェストで権限を明示する。**
GASは「必要な権限が増えた」と認識したときだけ同意画面を出すので、
認識されていないと、何度実行してもデプロイしても永久に出てこない。

1. エディタ左の ⚙️ **プロジェクトの設定**
2. 「**`appsscript.json` マニフェスト ファイルをエディタで表示する**」にチェック
3. 左のファイル一覧に現れる `appsscript.json` を、`gas/appsscript.json` の中身で置き換えて保存
   - 既存に `webapp` などの項目があれば消さず、`oauthScopes` の4行だけを足してもよい
   - `runtimeVersion` が `V8` でないときは `V8` に直す（コードがV8前提のため）
4. 関数プルダウンで **`診断`** を選んで実行（`gas/diagnose.gs` を貼っておく）
5. **ここで必ず承認画面が出る。**権限一覧に「Googleドキュメント」があることを確認して許可
6. もう一度 `診断` を実行し、ログが全部OKになることを確認
7. **そのあとで** デプロイ → デプロイを管理 → 鉛筆 → 新バージョン → デプロイ

7を先にやると、デプロイ済みのバージョンが古い承認のまま動いて同じエラーが続く。

**マニフェストを直しても承認画面が出ないとき**は、承認が「済み」の状態で固まっている。
一度アクセス権を捨てると必ず取り直しになる。**実際に今回これで解決した。**

1. https://myaccount.google.com/permissions を開く
2. 一覧からこのApps Scriptプロジェクトを探す（名前を変えていなければ `無題のプロジェクト`）
3. **アクセス権を削除**
4. Apps Scriptに戻って `診断` を実行 → 承認画面が出る
5. 権限一覧に「Googleドキュメント」「Googleドライブ」があることを確認して許可

あわせて確認すること。

- エディタ右上のアカウントが、スプレッドシートの持ち主と同じか
  （複数アカウントにログインしていると、別アカウントに承認が飛ぶ）
- `appsscript.json` の `oauthScopes` に `documents` と `drive` が入っているか

**それでも直らないとき**は、デプロイそのものを作り直すのが確実。
デプロイ → **新しいデプロイ** → ウェブアプリ（実行ユーザー：自分／アクセス：全員）で
新しい `.../exec` を発行し、`config.js` の `gasUrl` を差し替えてGitHubに上げ直す。
先方に配っているURLはGitHub Pages側なので、これを変えても先方への影響はない。

### 「承認されませんでした」と出るのに、実際は記録されている

2026年8月に実際に起きた不具合。原因は3つあって、全部直してある。

1. **送信の成否判定と画面の書き換えが同じ処理に入っていた。**
   書き換えの途中で例外が出ると、それも「送信失敗」として扱われていた。
   送信中にタブを切り替えるなどしてカードが画面から消えると、必ずこれが起きる。
   → 画面の書き換えは別扱いにして、失敗しても記録の成否には響かないようにした
2. **返事だけ受け取れなかったときに、そのまま失敗と決めつけていた。**
   回線の切り替わりやアプリの裏回りで起きる。サーバー側は記録できている。
   → 失敗に見えたら確認ログを見に行き、入っていれば成功として扱う（2回まで再確認）
3. **押し直しがそのまま重複ログになっていた。**
   → 同じ人・同じ投稿・同じ内容が1分以内に来たら、GAS側で記録済みとして返す。
   送信中は同じ投稿に対して二重に送らないようにもした

先方に「何度も押した」と言われたときは、**確認ログの重複行を消してよい。**
投稿確認シートのH列（ステータス）は最後の判定で上書きされているので、行を消しても影響はない。

### そのほか

- 確認者は `localStorage` に保存され、2回目以降は名前選択をスキップする。
  右上の「◯◯／切り替える」でいつでも変えられる
- 自分が確認した投稿は「あなたの確認：OK」＋**「変更する」**になる。
  押し直せばやり直せて、前の記録も確認ログに残る
- タブのバッジは「**自分がまだ見ていない**投稿の件数」
- 動画は自動再生しない。サムネイルをタップすると再生が始まる
